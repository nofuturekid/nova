# Google Play Data safety: answers for NOVA (`store` flavor)

Derived from the code of the `store` flavor on `origin/main` (2026-11-13, versionName 0.1.47) and checked against Google's definitions on <https://support.google.com/googleplay/android-developer/answer/10787469> (read 2026-11-13). Where Google's text does not settle a question, the answer is a judgement and marked **[judgement]**; the maintainer owns the form and enters it.

## Answers for the form

| Question                                                                  | Answer                         | Why                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Does your app collect or share any of the required user data types?       | **No** **[judgement]**         | Google: "'Collect' means transmitting data off a user's device", exempting on-device processing, end-to-end encryption and ephemeral processing. NOVA's developer receives nothing. What leaves the phone goes to the server the user runs themselves and to the icon hosts that server names. Google has no rule for a user-hosted server; the nearest case (the user's own cloud storage) is exempt when the app "never collects or accesses the data". Comparable self-hosted clients on Play state "no data collected". |
| Is all of the user data collected by your app encrypted in transit?       | **No**                         | Google's page lists this question (and the deletion question below) under the "Yes" branch of the first question; comparable listings (Jellyfin) still show "Data isn't encrypted", so if the form asks it, answer No. NOVA allows cleartext HTTP to the LAN (`AndroidManifest.xml:28`, `network_security_config.xml:15`), so it cannot claim "encrypted in transit". Answering "No" is the accurate statement.                                                                                                                            |
| Do you provide a way for users to request that their data is deleted?     | Not applicable                 | The developer holds no user data. Uninstalling removes all local data (`docs/privacy/POLICY.md`, "Your rights").                                                                                                                                                                                                                                                  |
| Independent security review                                               | No                             | None was done.                                                                                                                                                                                                                                                                                                                                                    |
| Families policy                                                           | Not committed                  | The target audience is 18 and over (`app-content.md`).                                                                                                                                                                                                                                                                                                             |
| Privacy policy URL                                                        | <https://github.com/hellwand/nova/blob/main/docs/privacy/POLICY.md> | Linked in the app under Settings, About (`SettingsScreen.kt:413`). Google asks for a "standard, non-editable webpage"; if a reviewer objects to a GitHub page, the policy can be copied to the project website (`site/`). Before the listing goes live, change the future-tense mention of Google Play in the policy.                                            |

If Google's form pushes for a different answer on the first row (for example because the server address and API key count as sent off-device), the fallback is: collected, **not** shared, purpose "App functionality", data types limited to what the user typed (server address, API key), and the note that it goes only to the user's own server. Record the outcome in ADR-0049 if that happens.

## Review risks noted while reading the code

- `Tls.kt:114-127` (`LocalPinningTrustManager`) catches the `CertificateException` of the platform's default manager, then lets the chain pass only when it is CA-valid or matches a fingerprint the user pinned; a first-seen certificate throws unless the user confirmed it, a changed one always throws (ADR-0041, `decidePinnedTrust`). It is not a trust-all manager, but Google's FAQ (<https://support.google.com/faqs/answer/6346016>) warns about `TrustManager`s that ignore certificate errors, and the pattern of catching the exception looks similar. Whether Play's scanner flags it is unknown: watch the pre-launch report after the first upload.
